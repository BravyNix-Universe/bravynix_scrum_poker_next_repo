# Bravynix Scrum Poker

Free, no-login Scrum Poker for poker.bravynix.com. Product and design documents are in [`doc/`](doc/), and the Stitch screens are in [`design/`](design/).

Built with Next.js (App Router), React, TypeScript and Tailwind CSS, exported as static files (`output: "export"`) for Hostinger. The code follows Clean Architecture; see [ARCHITECTURE.md](ARCHITECTURE.md).

## Requirements

Node.js 22.12 or later (see `.nvmrc`).

## Commands

```bash
npm install          # install dependencies
npm run dev          # local dev server at http://localhost:3000
npm run check        # typecheck, lint, format check and tests (run before every commit)
npm test             # unit and component tests (Vitest)
npm run lint:fix     # fix lint issues, including import order
npm run format       # format with Prettier
npm run build        # static export into out/
npm run avatars      # regenerate the avatar SVGs in public/avatars
```

Upload the contents of `out/` to the site's `public_html` to deploy.

## Project layout

```text
src/
  domain/          pure business rules (deck, results, limits, room IDs and links)
  application/     use cases, the room referee and the ports they need
  infrastructure/  adapters for browser APIs (Web Crypto, Web Storage, IndexedDB, PeerJS) and the preview room session
  composition/     wires adapters to ports
  app/             Next.js routes
  features/        feature screens and hooks (landing, create-room, my-rooms, room)
  components/      shared UI kit and layout
  lib/  config/    UI helpers and site settings
  test/            test setup and fakes
public/avatars/    avatar images, generated by scripts/generate-avatars.mjs
```

## Live rooms

Rooms are peer to peer (PRD 6, SDD 9). The host's browser runs the room: everyone else connects to it over WebRTC, and it signs every change it sends out. Votes stay sealed until the host reveals. No server stores a room; each device keeps its own copy in IndexedDB until the room expires 24 hours after it was created.

Devices find each other through a PeerJS connection service. By default that is the free PeerJS cloud (`0.peerjs.com`), which only introduces devices and never sees room content. Once introduced, devices talk directly, or through a relay when a network blocks direct connections.

To try a room on one computer, open it in two different browser profiles (or a normal and a private window): the host link in one, the invite link in the other. Two tabs of the same profile share storage, so the second tab would also act as the host and show "This room is open in another tab or device".

### Settings

Settings are read at build time. Copy [`.env.example`](.env.example) to `.env.local` and fill in what you need:

| Variable                  | Default      | Meaning                                                                 |
| ------------------------- | ------------ | ----------------------------------------------------------------------- |
| `NEXT_PUBLIC_ROOM_MODE`   | live         | `preview` runs rooms in one tab with simulated teammates (see below)    |
| `NEXT_PUBLIC_PEER_HOST`   | PeerJS cloud | Host name of your own PeerServer; leave empty to use PeerJS cloud       |
| `NEXT_PUBLIC_PEER_PORT`   | 443          | Its port                                                                |
| `NEXT_PUBLIC_PEER_PATH`   | `/`          | The path it is mounted at                                               |
| `NEXT_PUBLIC_PEER_SECURE` | `true`       | `false` for a plain `http` PeerServer, such as one on your own computer |

To run your own PeerServer locally:

```bash
npx peer --port 9000
```

then set `NEXT_PUBLIC_PEER_HOST=localhost`, `NEXT_PUBLIC_PEER_PORT=9000` and `NEXT_PUBLIC_PEER_SECURE=false`, and restart `npm run dev`.

## Preview mode

With `NEXT_PUBLIC_ROOM_MODE=preview`, a room runs as an in-tab preview: teammates are simulated and nothing leaves the browser tab. They join, vote and open their cards when you reveal. Open the invite link in a private window to see the participant view, where a simulated host also reveals and moves through the stories.

To review the connection screens without a network, open **Connection details** (the connection indicator in the top bar, or the room menu) and pick a situation under **Preview: act out a situation**: a dropped connection, the host stepping away, 24 more people joining, or each "can't connect" page. Those pages' **Try again** brings you back to the room.
